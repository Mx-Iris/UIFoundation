摘要

AppKitPlus 0.24.0 给 NSLayerBackedView 加了 cornerRadius、cornerCurve、backgroundColor、borderColor、borderWidth、borderPositions、borderLocation、borderInsets 与 shadowProperties。开着 AppKitPlus trait 时 LayerBackedView 继承 NSLayerBackedView，这些 Objective-C 类成员在名字查找上压过 LayerBackgroundProviding 协议扩展里的同名属性：调用方设的值进了 AppKitPlus，本库的 LayerBackgroundRenderer 什么也收不到，却仍在每次 updateLayer() 里用自己的默认值（圆角 0、背景 nil）把 layer 改回去。结果是所有经 LayerBackedView 设的圆角和背景色都没了——RuntimeViewer 的欢迎窗口变成直角就是这样来的。

本提案按 AppKitPlus 0122 当初定好的分工收尾：trait 打开时，LayerBackedView 不再遵循 LayerBackgroundProviding、不再挂 renderer，外观全部交给 AppKitPlus 自己的成员；AppKitPlus-Release 的下限从 0.6.0 提到 0.24.0；为保持源码兼容，trait 下补上 shadowColor 等五个阴影属性，转写到 shadowProperties；borderPositions 在 trait 下仍默认空集合，与 trait 关闭时一致。trait 关闭时一行不变。随 0.51.0 发布。

提议方案

  1. trait 打开时 LayerBackedView 的外观归 AppKitPlus：不遵循 LayerBackgroundProviding，构造时不挂 renderer，updateLayer() 和 layout() 不再调 renderer。trait 关闭时保持原样。
  2. AppKitPlus-Release 下限提到 0.24.0：trait 下的代码要用 shadowProperties 与 AppKitPlus 的外观成员；只要范围里还允许旧版本，同样的组合就会再出现。
  3. trait 下补阴影五项：shadowColor、shadowOpacity、shadowOffset、shadowRadius、shadowPath 读写 shadowProperties；shadowColor = nil 写成 .clear。
  4. trait 下 borderPositions 仍默认空集合：同一个类型的默认值不该随 trait 变。
  5. 哨兵测试改成与归属无关的断言，两种 trait 下都要过；本库自己的锁文件把 AppKitPlus 抬到 0.24.0。
  6. 随 0.51.0 发布，之后 RuntimeViewer 把本库下限抬到 0.51.0。

非目标

  • 不改 trait 关闭时的任何行为，也不改 LayerBackgroundRenderer 本身。
  • 不让 trait 下的 LayerBackedView 拿回 renderer 的阴影默认值：没有调用方依赖，硬塞会让「没设过阴影」变成「设过阴影」，AppKitPlus 会因此关掉裁剪。
  • 不废弃阴影五项、不改名。
  • 不处理 NSLayerBackedControl / NSLayerBackedTableCellView：本库没有类继承它们。
  • 不修 AppKitPlus 自己的实现；对照测试发现差异就记录并报给上游。
  • RuntimeViewer 一侧的升级属于它自己的提交。

详细设计

LayerBackedView.swift（只列变化的部分） 
@IBDesignable
open class LayerBackedView: LayerBackedViewBase {
    open var isLayerBackingEnabled: Bool { true }

    private func commonInit() {
        #if AppKitPlus && canImport(AppKitPlus)
        // AppKitPlus draws a border along every edge by default; this class has always drawn none
        // until the edges are named, with the trait on or off.
        borderPositions = []
        #else
        attachToSelfIfNeeded()
        #endif
        setup()
    }

    open override func layout() {
        super.layout()
        _firstLayout()
        #if !(AppKitPlus && canImport(AppKitPlus))
        layoutLayerBackgroundIfNeeded()
        #endif
    }

    open override func updateLayer() {
        super.updateLayer()
        #if !(AppKitPlus && canImport(AppKitPlus))
        updateLayerBackgroundIfNeeded()
        #endif
    }

    open override var wantsUpdateLayer: Bool { isLayerBackingEnabled }
}

#if !(AppKitPlus && canImport(AppKitPlus))
extension LayerBackedView: LayerBackgroundProviding {}
#endif

updateLayer() 的覆写保留，让两种 trait 下的继承链形状一样；isLayerBackingEnabled 继续是类自己的 open 成员。

LayerBackedView+Shadow.swift（仅 trait 下编译） 
extension LayerBackedView {
    /// The shadow's colour. `nil` draws no shadow. Unset, this reads AppKitPlus's default, black.
    public var shadowColor: NSColor? {
        get { shadowProperties.color }
        set { shadowProperties.color = newValue ?? .clear }
    }
    public var shadowOpacity: Float {
        get { Float(shadowProperties.opacity) }
        set { shadowProperties.opacity = CGFloat(newValue) }
    }
    public var shadowOffset: CGSize { get { shadowProperties.offset } set { shadowProperties.offset = newValue } }
    public var shadowRadius: CGFloat { get { shadowProperties.radius } set { shadowProperties.radius = newValue } }
    public var shadowPath: NSBezierPath? { get { shadowProperties.path } set { shadowProperties.path = newValue } }
}
类型差异与测试

trait 下 borderPositions 的类型是 NSLayerBackedView.BorderPositions、borderLocation 是 NSLayerBackedView.BorderLocation（今天已经如此）。写 .all、[.top, .bottom]、.center 的调用点两种 trait 下都能编；显式写出 LayerBackgroundRenderer.BorderPositions / BorderLocation 的会在 trait 下编不过。本库 Sources/ 与所有下游都没有这种写法，唯一的一处在 LayerBackgroundCornerCurveTests 的帮手里，改成按 trait 定的别名 TileBorderLocation。

  • appearanceReachesTheLayer：设红色背景与 8 点圆角，刷新一次后 layer 的值正确。无窗口测试里怎么触发 AppKit 写回 layer，第 1 步实测后定。
  • bordersStayOffUntilEdgesAreNamed：只设颜色和宽度，不画边框。
  • shadowMembersForwardToShadowProperties（trait 下）：五项写入后读 shadowProperties；shadowColor = nil 后是 .clear。
  • xcode26WindowContentIsRounded：经 (panel as NSWindowController).window 取窗口，内容视图 layer 圆角 20、masksToBounds 为真。

前期调研

冲突的机制、AppKitPlus 0.24.0 的成员、默认值差异、下游清点
  • 冲突怎么发生的：LayerBackedView（LayerBackedView.swift:33）在 trait 下继承 NSLayerBackedView 并遵循 LayerBackgroundProviding；外观属性全是协议扩展成员（LayerBackgroundProviding.swift:39 起）。具体类型上调用时 Swift 先找到类成员，不再看协议扩展。
  • renderer 为什么会把值改回去：LayerBackgroundRenderer.updateLayer()（LayerBackgroundRenderer.swift:133）无条件写圆角、背景、阴影四项和 masksToBounds。
  • AppKitPlus 0.24.0 的成员：cornerRadius、backgroundColor 转发到 AppKit 自己的同名私有成员；cornerCurve、border* 由视图自己写、颜色随外观重解析；阴影是 shadowProperties: NSShadowProperties（color: NSColor、opacity: CGFloat、radius、offset、path）；没人设过的成员从不写；裁剪用 AppKit 的 clipsToBounds，有阴影时不裁剪。
  • 阴影五项没有同名类成员：AppKitPlus 0.24.0 公开头文件里只有 NSLabel.h（文字阴影，不在同一继承链）和 NSLayerBackedView.h 的一处注释。
  • 没有下游泛型地使用这条管线：全部本地仓库里只有 LyricsX 的 InteractionToggleButton 自己遵循协议，不经 LayerBackedView。RuntimeViewer、本库、示例 App 设边框都显式写了 .all，都没用阴影五项。
  • LayerBackedTableCellView 不受影响：它继承 TableCellView: NSTableCellView，类上没有这些成员。
  • 锁文件的解析坑：带包名的 swift package --traits AppKitPlus update AppKitPlus-Release 实测能把 pin 写成 0.24.0，与 AGENTS.md 现有记录不同，落地时补记。

替代方案

五条，均否决
  • renderer 继续独占外观，覆写 AppKitPlus 的九个成员：边框类型是 AppKitPlus 的，两套声明要分别维护；绕开 AppKitPlus 的颜色重解析；违背 0122 的分工。
  • 保留协议遵循，只让 renderer 不写 layer：协议扩展的阴影五项和 attachToSelfIfNeeded() 会静默无效，正是这次事故的形状。
  • trait 下改用 AppKitPlus 的默认值 .all：默认值随 trait 变，只设颜色和宽度的地方会多出边框。
  • 不抬下限，用版本判断兼容旧版：二进制包的模块版本不可靠，旧版也没有 shadowProperties。
  • 只在 RuntimeViewer 一侧绕开：问题在本库，76 处都会坏；退回 0.23.0 还会失去 Responder Debugger。

影响

源码兼容性

  • trait 关闭：不变。
  • trait 打开：LayerBackedView 不再遵循 LayerBackgroundProviding，把它当协议类型用或调 attachToSelfIfNeeded() 等的代码编不过；已查无此类调用点，不提供过渡。
  • 行为差异：阴影偏移与半径默认零和 0；shadowColor 未设时读到黑色；分边边框内缩四边各算；有阴影时不裁剪子视图。
  • trait 打开的使用方，AppKitPlus 要能解析到 0.24.0 及以上。

ABI 兼容性

不适用 —— 本库以 SPM 源码分发，使用方每次重新编译。

下游影响

  • RuntimeViewer（AppKitPlus 0.24.0 + 本库 0.50.1，已中招）：0.51.0 发布后把 UIFoundation 下限改为 from: "0.51.0"，三个工作区的锁文件只抬这一个 pin，Dependency floors 补一句；之后目视欢迎窗口、Load Frameworks 横幅、Open Quickly 输入框、编辑区分隔短线。
  • PrivateSymbols、LaunchpadAwakener、MacKedUpdater、XCOrganizer、MachOKitUI（开着 trait，AppKitPlus 0.18.0–0.22.0）：现在没事；升到 0.51.0 会被带到 AppKitPlus 0.24.0，各自做碰撞清点。
  • LyricsX：trait 关闭，不受影响。
  • 本仓库：经 LayerBackedView 设外观的组件在 trait 下改由 AppKitPlus 画；示例 App 要重新构建并看 LayerBackground 演示页。

API 演进

  • 不废弃任何 API：阴影五项在 trait 关闭时是正式 API，只在一侧废弃会让同一行代码随 trait 出不出警告。
  • 版本号：0.x 里按次版本发，0.51.0。
