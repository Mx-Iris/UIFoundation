摘要

UIFoundationSettingsUI 里写页面要用的四样东西——AppSettings（把一项设置绑到 SwiftUI 控件的属性包装）、SettingsForm、SettingsPage 与它的 result builder、SettingsPageIcon——放开到 iOS、Mac Catalyst 与 visionOS，同一份 SwiftUI 页面两边都能编；另加一个 iOS 用的宿主：SwiftUI 的 SettingsNavigationStack（页面列表，点进去是页面内容，像系统「设置」App）和包着它、给 UIKit App 弹出用的 SettingsViewController，与 macOS 的 SettingsWindowController 对称。macOS 的设置窗口一行不改。

关联

  • 所属愿景：无（下游 RuntimeViewer 的愿景《iOS 版功能对齐》要用它做 iOS 设置页）
  • 关联提案：0042-settings-store-on-all-platforms（设置存储已在各平台可用）、0002-reusable-settings-window（设置窗口的来历）；下游 RuntimeViewer 的 draft-settings-screen-on-ios
  • 配套文档：无单独文档——改现有指南 SettingsWindow.md
  • 网页版：同目录同名的 .html

动机

  • 下游要在 iOS 上复用设置页：RuntimeViewer 的设置页都是 SwiftUI，但写在 @AppSettings 与 SettingsForm 上，这两样连同 SettingsPage 都包在 #if Settings && os(macOS) 里（Sources/UIFoundationSettingsUI/AppSettings.swift:1、SettingsForm.swift:1、SettingsPage.swift:1）。它的愿景《iOS 版功能对齐》定了「设置页复用 SwiftUI 页面、宿主换成 UIKit」，不在下游另写一套。
  • 这几样本来就不碰 AppKit：AppSettings、SettingsForm、SettingsPage 只用 SwiftUI 与 UIFoundationSettings；SettingsPageIcon 只有一处用 NSImage(systemSymbolName:) 判断符号是否存在（SettingsPageIcon.swift:80-86）。
  • iOS 没有设置窗口这种东西：macOS 的宿主是带侧栏的窗口（SettingsWindowController、SettingsRootView、SettingsScene），iOS 的习惯是一张列表、点进去一页；需要一个对应的宿主，下游才不必各自拼。

提议方案

  1. 四样共用的组件放开：AppSettings.swift、SettingsForm.swift、SettingsPage.swift、SettingsPageIcon.swift 的条件改为 #if Settings && (os(macOS) || os(iOS) || os(visionOS))（Mac Catalyst 上 os(iOS) 为真），@available 补 iOS 17.0, macCatalyst 17.0, visionOS 1.0；SettingsPageIcon 判断符号是否存在时按平台用 NSImage 或 UIImage。
  2. iOS 的宿主（新文件，#if Settings && (os(iOS) || os(visionOS))）：
    • SettingsNavigationStack：SwiftUI 视图，NavigationStack 里一张 List，每行是页面图标加标题，点进去显示页面内容，标题栏是页面标题；根页右上角一个「完成」按钮，按下调用传入的 onDone（不传就用环境里的 dismiss）。
    • SettingsViewController：open class，把 SettingsNavigationStack 装进一个 UIHostingController 子视图控制器，「完成」时 dismiss(animated:)；初始化器与 macOS 的 SettingsWindowController 同形：init(title:pages:)，页面用 @SettingsPageBuilder 给。
  3. 文档：SettingsWindow.md 的平台说明改为「写页面的组件各平台可用，宿主分平台」，加一节「在 iOS 上」；AGENTS.md 项目地图里 UIFoundationSettingsUI 一行写清两边各有什么。

非目标

  • macOS 设置窗口的任何变化。
  • iPad 上的双栏设置（左列表右内容）：先一律用单栏的导航栈，iPad 上以 sheet 弹出时同样适用。
  • tvOS 与 watchOS。
  • SettingsNavigator 与 SettingsConfiguration 跨平台：它们描述的是侧栏窗口，iOS 宿主用不到。
  • 把设置模块并进伞模块。

详细设计

SettingsNavigationStack 与 SettingsViewController 
#if Settings && (os(iOS) || os(visionOS))
import SwiftUI

/// The settings pages as iOS presents them: a list of pages, each pushing
/// its content, with a Done button on the list.
@available(iOS 17.0, macCatalyst 17.0, visionOS 1.0, *)
public struct SettingsNavigationStack: View {
    public init(
        title: String = "Settings",
        onDone: (() -> Void)? = nil,
        @SettingsPageBuilder pages: () -> [SettingsPage]
    )

    public var body: some View   // NavigationStack { List(pages) { NavigationLink … } .navigationTitle(title) .toolbar { Done } }
}

/// Presents the settings pages from a UIKit app — the counterpart of the
/// macOS `SettingsWindowController`. Subclass it to give the pages once.
@available(iOS 17.0, macCatalyst 17.0, visionOS 1.0, *)
@MainActor
open class SettingsViewController: UIViewController {
    public let pages: [SettingsPage]

    public init(title: String = "Settings", @SettingsPageBuilder pages: () -> [SettingsPage])

    override open func viewDidLoad()   // embeds UIHostingController(rootView: SettingsNavigationStack(…, onDone: dismiss))
}
#endif
  • 列表行：SettingsPageIcon(page.icon, size: 29) 加 Text(page.title)；plainSymbol 图标在 iOS 上画成单色符号，与系统「设置」的彩色方块不同，页面要彩色方块就用 .symbol(_, tint:)。
  • SettingsPage.content 已是 @MainActor 的 AnyView，NavigationLink(value: page.id) 配 navigationDestination 取页面。
  • 「完成」按钮的文字用模块的本地化资源（已有 Localizable.xcstrings），新增一条 Done。

前期调研

可直接放开的

AppSettings（AppSettings.swift，64 行）用 Root.store.value 与 @Bindable，@Bindable 需要 iOS 17；SettingsForm（32 行）是 Form { }.formStyle(.grouped)，iOS 16 起有；SettingsPage 与 SettingsPageBuilder（117 行）只有 SwiftUI 类型。依赖的 UIFoundationSettings 自 0042 起各平台可用（iOS 17、Catalyst 17、visionOS 1）。

要改一处的

SettingsPageIcon.image(named:) 判断 SF Symbol 是否存在用的是 NSImage(systemSymbolName:accessibilityDescription:)；UIKit 上的对应是 UIImage(systemName:)。

留在 macOS 的

SettingsWindowController、SettingsWindowSupport、SettingsRootView、SettingsScene、SettingsConfiguration（窗口尺寸与侧栏）、SettingsNavigator（侧栏的选择与前进后退历史；iOS 上由 NavigationStack 自己管）。

target 结构

UIFoundationSettingsUI 依赖 UIFoundationSettings，另在 macOS 上依赖 UIFoundationAppKit（Package.swift 的 UIFoundationSettingsUI target），带一个本地化资源包（返回、前进按钮的文字）。其他平台上它现在是空模块。

平台范围

Observation 与 @Bindable 要 iOS 17 / Catalyst 17 / visionOS 1；tvOS 与 watchOS 没有这类设置界面的用法，且 Xcode 27 已编不了本包声明的 tvOS 13 / watchOS 6 下限（0042 的决策日志），不纳入。

使用方

RuntimeViewer 的 macOS 设置窗口；ReverseEngineeringToolbox、MacKedUpdater、XCOrganizer 都是 macOS App，不受影响。

替代方案考量

3 个方案，均未采用
  • 只放开组件，不提供 iOS 宿主：每个下游各写一份列表加导航，形状会各不相同。宿主不到百行，放在库里。
  • iOS 上也做侧栏窗口的样子（UISplitViewController）：iPhone 上会折叠成导航栈，iPad 上的双栏留作后续。
  • SettingsViewController 直接继承 UIHostingController：泛型根视图让子类化很别扭，下游子类还得写出根视图类型；包一层子视图控制器更像 macOS 的 SettingsWindowController。

影响

源码兼容性（source compatibility）

纯新增。macOS 上的类型、行为都不变；放开的四样在其他平台上原来不存在。

ABI 兼容性（条件项）

不适用 —— 本库以 SPM 源码分发，使用方每次重新编译。

下游影响

  • 本仓库：UIFoundationSettingsUI 在 iOS、Catalyst、visionOS 上从空模块变成有内容。
  • RuntimeViewer：iOS 设置页用它（draft-settings-screen-on-ios），下限抬到本次发版。
  • ReverseEngineeringToolbox、MacKedUpdater、XCOrganizer：只在 macOS 上用，不受影响。
